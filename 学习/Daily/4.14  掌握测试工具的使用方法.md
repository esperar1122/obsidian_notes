- pattern：own address：表示当前使用的数据模式是”写入自己的地址“，验证内存单元是否能准确存储特定的数据。如果内存坏了，写入的是地址吗，读出来可能是乱码

<F1>测试项目选择：
- 选择要运行的具体内存测试算法
- Memtest包含多种算法：移动反相，随机数填充、位翻转等，每种算法针对不同类型的内存故障，默认通常是ALL Test。
核心测试算法：
- Test #0： Address test，walking ones：地址线测试（走位1）：主要检测内存的地址线是否有短路或断路。 
- Test #1： Address test，own addres：地址线测试（自身地址）：向内存写入自己的地址值，然后读出来比对。这是检测地址线故障的基础测试 
- Test #2：[Moving inversions，ones & zeroes]：移动反相（1和0）。先填满0再逐个反转为1；然后填满1，再逐个反转为0.能有效发现大多数stuck-at（卡死）故障。 
- Test #3： [Moving inversions，8-bit pattern]：移动反相（8位模式）。使用0x80（10000000）和0x7F（01111111）这样的8位模式进行移动反相测试。
- Test #4： [Moving inversions, random pattern]：移动反相（随机模式）。使用随机生成的数据进行上述的“移动反相”。因为数据不可预测，能发现更多偶发性故障。
- Test #5： [Block move，64 moves]：块移动测试。在内存的不同区域之间大量复制数据块。主要检测内存控制器在搬运数据时是否出错，或者是否有数据“串扰”。
- Test #6： [Moving inversions，32-bit pattern]：移动反相（32位模式）。使用32位的复杂模式（如`0x80000000`）进行测试，检查数据总线的宽位故障。
高级压力测试：
- Test #7：[Random number sequence]随机数序列测试。生成随机数写入内存并校验。用于检测逻辑电路中的随机错误。 
- Test #8： [Modulo 20，ones & zeros]模20测试。一种针对特定地址映射错误的测试，能发现某些特定硬件架构下的寻址bug
- Test #9：[Bit fade test]位衰减测试。写入数据后等待一段时间再读取。用于检测电容漏电。
- Test #10：[Hammer test]/Row Hammer]锤击测试。会疯狂反复地读写相邻的内存行，试图通过电磁干扰让旁边的内存位发生反转。这检测DDR4/DDR5行锤击漏洞和稳定性的关键。

<F2>地址范围：
- 选择要测试的内存物理地址范围
- 允许只测试内存的特定部分
- 默认通常是 All Available Ram（所有可用内存）
- 使用场景：知道内存的某个特定区域（如2GB-3GB）总是报错，可以设置到这个范围

<F3>CPU 排序模式：
- 控制多核CPU如何协同进行测试
- 1.Parallerl模式(PAR)：并行模式，所有CPU核心同时测试不同内存区域。速度最快。
- 2.Sequential模式(SEQ)：串行模式，一个一个核心测，用于排查是否是某特定CPU核心导致的内存错误。
- 3.Round Robin（RR）：轮询模式，所有CPU排队使用内存，在怀疑CPU内存控制器不稳定，或者电脑测试时容易过热死机时使用。

<F4>错误报告模式：
- 当发现错误使，屏幕如何显示
- 选项：
	- Error counts only：摘要模式。只在Errors上计数加1，不显示具体错误细节。
	- Error summary：错误摘要。显示错误的统计信息。
	- Individual errors：详细模式。每发现一处错误，都会列出详细的错误地址和数据。适合需要记录具体坏块位置。
	- BadRam patterns：BadRAM模式。生成一种特殊的代码输出，可以用来告诉Linux内核：这几段地址坏的要避开，剩下的还能继续用。

<F5>跳过当前测试：
- 立即停止当前正在进行的算法，直接进入下一个算法
- 如果觉得当前测试太慢，且确定这部分没有问题，可以跳过。

本文核心围绕**测试人员日常工作高频使用、必须掌握**的服务器知识展开，剔除运维级的深度底层内容，聚焦测试环境搭建、问题定位、用例执行、性能 / 接口测试等核心工作场景。

## 一、服务器核心定义与测试的强关联

服务器是提供计算、存储、网络、应用服务的高性能计算机，是所有软件系统的运行载体，也是测试工作的核心基础设施：

- 功能 / 接口测试：被测系统、接口服务、数据库均部署在服务器上，测试的前提是服务正常运行；
- 性能测试：通过对服务器加压，监控资源指标，定位系统性能瓶颈；
- 自动化测试：自动化脚本、持续集成 (CI/CD) 任务、测试平台均需部署在服务器上稳定运行；
- 问题定位：80% 以上的测试环境异常，都需要通过服务器日志、进程、资源状态排查根因。

## 二、测试场景高频接触的服务器分类

### 1. 按业务用途分类（测试人员每日接触）

表格

| 服务器类型         | 核心作用                                                       | 测试相关核心操作                            |
| :------------ | :--------------------------------------------------------- | :---------------------------------- |
| 应用服务器         | 运行被测业务系统，如 SpringBoot、Tomcat、Jetty 服务，处理业务逻辑与接口请求          | 服务启停、配置修改、日志查看、版本更新、进程排查            |
| 数据库服务器        | 存储业务数据，分为关系型 (MySQL/Oracle) 和非关系型 (Redis/MongoDB)          | 数据造数、数据校验、慢 SQL 排查、缓存有效性验证、事务一致性测试  |
| 中间件服务器        | 承载微服务核心组件，如消息队列 (Kafka/RabbitMQ)、注册中心 (Nacos)、网关 (Gateway) | 消息生产消费验证、路由规则测试、限流熔断验证、分布式锁测试       |
| Web / 反向代理服务器 | 以 Nginx/Apache 为主，负责请求转发、负载均衡、静态资源托管、跨域配置                  | 路由正确性验证、负载均衡有效性测试、跨域配置校验、HTTPS 证书验证 |
| 压测服务器         | 独立部署压测工具 (JMeter/Locust)，专门用于性能压测的施压端                      | 压测脚本部署、并发任务执行、施压端资源监控，避免本机压测的资源瓶颈   |
| 堡垒机 / 跳板机     | 登录生产 / 预发布环境的统一入口，用于权限管控与操作审计                              | 合规登录目标服务器、执行授权范围内的日志查看与问题排查         |

### 2. 按部署形态分类

- **云服务器 (ECS)**：测试环境 90% 以上的选择，阿里云、腾讯云等厂商提供的弹性云主机，可快速申请、销毁、扩容，适配多项目测试环境隔离需求；
- **虚拟机**：通过 VMware/KVM 从物理机虚拟化出的独立主机，常用于内网测试环境，实现一台物理机承载多套隔离的测试环境；
- **容器化环境**：Docker+K8s，当前微服务测试的主流部署方式，可实现测试环境一键部署、版本快速回滚，测试人员需掌握容器的启停、日志查看、配置修改；
- **物理服务器**：实体高性能主机，仅用于生产核心业务或对性能要求极高的压测场景，测试环境极少直接使用。

## 三、服务器核心硬件基础（性能测试必懂）

无需深入硬件原理，重点掌握硬件参数对测试结果、系统运行的影响，核心是性能测试的瓶颈定位：

1. **CPU**：核心数、主频决定服务器的计算能力，性能测试核心监控指标为**CPU 使用率**，压测中 CPU 持续占用 90% 以上，是最常见的系统性能瓶颈；
2. **内存 (RAM)**：决定服务器并发处理能力与服务运行稳定性，Java 服务的 JVM 堆内存直接受限于服务器内存，测试中高频遇到的**内存溢出 (OOM)**、服务卡顿，均与内存相关；
3. **存储**：分为 HDD 机械硬盘和 SSD 固态硬盘，核心指标是**IO 读写性能**，数据库服务器、文件服务器的核心瓶颈点，大量数据造数、批量接口测试时，磁盘 IO 不足会导致接口响应超时；
4. **网卡**：核心指标是带宽（千兆 / 万兆），决定网络传输能力，接口压测、大文件上传下载测试中，带宽不足会导致并发上不去、压测结果失真。

## 四、服务器操作系统核心基础

测试环境 95% 以上使用 Linux 操作系统，是测试人员必须掌握的核心，Windows Server 仅用于.NET 框架等特殊业务系统，了解即可。

### 1. 主流 Linux 发行版

- CentOS：国内测试环境最常用的发行版，社区文档丰富，适配绝大多数中间件与应用；
- Rocky Linux/AlmaLinux：CentOS 停更后的主流替代方案，操作命令与 CentOS 完全兼容；
- Ubuntu：多用于个人开发、云原生场景，操作略有差异，核心命令通用。

### 2. 测试人员必备 Linux 核心命令

按测试工作高频场景分类，覆盖 90% 以上的日常操作：

#### （1）远程登录与基础文件操作

bash

运行

```
ssh 用户名@服务器IP  # 远程登录服务器，测试人员操作服务器的第一步
cd/ls/pwd/mkdir/rm/cp/mv  # 目录切换、文件查看、新建/删除/复制/移动，基础必备
vi/vim  配置文件路径  # 编辑服务配置文件，如修改application.yml、nginx.conf
```

#### （2）服务进程管理（服务启停、异常排查高频）

bash

运行

```
ps -ef | grep 服务名  # 查看服务进程是否启动，如ps -ef | grep tomcat
kill -9 进程PID  # 强制终止异常进程，重启服务前常用
systemctl start/stop/restart/status 服务名  # 管理系统服务，如nginx、mysql、docker
nohup java -jar xxx.jar &  # 后台启动SpringBoot jar包服务，测试部署最常用
```

#### （3）日志查看（Bug 定位核心，每日必用）

bash

运行

```
tail -f 日志文件路径  # 实时查看服务运行日志，复现Bug时同步看报错
tail -n 1000 日志文件路径  # 查看日志文件最后1000行内容
grep 关键词 日志文件路径  # 搜索日志中的报错信息，如grep Exception catalina.out
less 日志文件路径  # 翻页查看大体积日志文件，支持关键词搜索，比cat更高效
```

#### （4）网络排查（接口不通、服务访问异常首选）

bash

运行

```
ping 服务器IP  # 验证本地与服务器网络是否连通
telnet 服务器IP 端口号  # 验证服务端口是否开放、可访问，接口调不通第一步排查
netstat -tulpn | grep 端口号  # 查看端口被哪个进程占用，解决服务启动端口占用报错
curl 接口地址  # 命令行直接调用接口，快速验证接口可用性，无需Postman
```

#### （5）系统资源监控（性能测试核心）

bash

运行

```
top  # 实时查看CPU、内存使用率，进程资源占用情况
free -h  # 查看服务器内存总容量、已用/剩余容量，排查内存溢出问题
df -h  # 查看磁盘使用率，解决磁盘满导致的服务崩溃、日志无法写入问题
vmstat/iostat  # 查看系统整体负载、磁盘IO性能，定位性能测试瓶颈
```

#### （6）文件传输

bash

运行

```
rz  # 从本地上传文件到服务器，如jar包、配置文件（需先安装lrzsz）
sz 文件名  # 从服务器下载文件到本地
scp 本地文件 用户名@服务器IP:目标路径  # 跨服务器/本地与服务器传输文件
```

## 五、测试高频接触的服务与中间件基础

### 1. Nginx（Web / 反向代理服务）

- 核心能力：反向代理（前端请求转发到后端应用）、负载均衡、静态资源托管、跨域配置、HTTPS 配置、限流控制；
- 测试核心关注点：路由转发规则是否正确、负载均衡策略是否生效、跨域配置是否正常、限流熔断是否符合预期、HTTPS 证书是否有效。

### 2. Tomcat（应用服务容器）

- 核心能力：运行 Java Web 应用、SpringBoot/SpringCloud 服务，处理 HTTP 请求，管理 Servlet 生命周期；
- 测试核心关注点：服务端口配置、JVM 参数调整（性能测试必备）、日志输出配置、连接池参数、会话保持配置，以及服务启动异常、日志报错排查。

### 3. 数据库服务

- 关系型数据库（MySQL/Oracle）：核心用于结构化数据存储，测试需掌握基础的 CRUD 语句、数据一致性校验、事务回滚验证、慢 SQL 定位；
- 非关系型数据库（Redis 为主）：核心用于缓存、分布式锁、热点数据存储，测试需验证缓存是否命中、缓存击穿 / 雪崩场景、分布式锁是否生效、数据过期策略是否正确。

### 4. 消息队列（RabbitMQ/Kafka）

- 核心能力：系统异步解耦、流量削峰，微服务架构核心组件；
- 测试核心关注点：消息生产与消费是否正常、消息是否丢失 / 重复消费、死信队列是否生效、消息积压场景下的系统稳定性，以及消息吞吐量性能测试。

### 5. Docker/K8s（容器化与编排）

- Docker：将应用与依赖打包成镜像，实现 “一次打包，到处运行”，彻底解决 “本地能跑，服务器跑不了” 的环境问题；测试人员需掌握镜像拉取、容器启停、日志查看、进入容器、配置挂载等操作；
- K8s（Kubernetes）：容器编排工具，管理多服务器上的容器集群，大厂测试环境主流部署方式；测试人员需掌握 Pod 状态查看、Pod 重启、日志查看、配置修改等基础操作。

## 六、测试工作中服务器核心场景与操作规范

### 1. 测试环境问题排查通用流程（高频必备）

1. **服务访问不了**：先 ping 服务器 IP 确认网络连通 → telnet 端口确认端口开放 → ps 查看服务进程是否正常启动 → 查看服务启动日志是否有报错 → 检查防火墙 / 安全组是否放通端口与 IP；
2. **接口调用报错**：先确认接口参数、请求方式是否正确 → 查看前端控制台 / 网关日志是否转发成功 → 查看应用服务日志是否有异常堆栈 → 校验数据库 / 缓存是否正常运行 → 检查服务间依赖是否可用；
3. **服务启动失败**：查看启动日志定位报错原因 → 检查端口是否被占用 → 校验配置文件语法与内容是否正确 → 确认 JDK / 依赖版本是否匹配 → 检查磁盘 / 内存是否充足。

### 2. 性能测试服务器核心要点

- 压测前：确认施压服务器与被测服务器网络互通、带宽充足，配置好服务器资源监控，关闭测试环境无关程序，避免资源占用影响压测结果；
- 压测中：实时监控 CPU、内存、磁盘 IO、网络带宽、系统负载、JVM GC、数据库慢 SQL 等核心指标；
- 压测后：基于监控指标定位性能瓶颈，如 CPU 持续高占用、内存泄漏、磁盘 IO 瓶颈、慢 SQL 过多等，输出优化建议。

### 3. 服务器操作红线（必须严格遵守）

1. 严禁在无审批、无运维陪同的情况下，在生产服务器执行任何测试操作、修改配置、启停服务；
2. 严禁执行`rm -rf /`等高危命令，使用 rm 删除文件前，必须确认目录路径，避免误删系统文件；
3. 严禁随意修改预发布 / 生产环境配置，测试环境修改配置前必须备份，确保可回滚；
4. 严禁泄露服务器 IP、账号密码、密钥等敏感信息，做好权限管控；
5. 严禁在测试服务器部署与测试无关的程序，避免占用资源，导致测试结果失真。
